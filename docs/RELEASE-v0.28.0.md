# FpiUpdates v0.28.0

## Included
- Black-background installation icons, clear white mark and dedicated notification badge. Browser theme colour follows light/dark/system appearance where supported.
- `/install` with Android, iPhone/iPad and desktop guidance; existing install menu retained; footer link; optional dismissible feed installation card (30-day local dismissal). No repeated native installation prompts.
- Observed installation/standalone-use measurement with existing opt-out and DNT/GPC support. Admin Analytics Overview shows platform breakdown, observed active installations over 30 days and registered push subscriptions. Standalone activity is measured at most once per browser/UTC day. These are browser observations, not exact physical devices or known uninstall counts.
- Background Web Push subscription/disable/test controls in Settings → Notifications; stable VAPID configuration script; 15-second background checks, bounded batches, retry backoff, expired endpoint cleanup, session expiry/revocation checks and logout cleanup. Existing in-app polling remains.
- Push covers existing notification-inbox activity: likes, replies, mentions, follows, reposts, quotes and enabled followed-account alerts. **Private-message background push is not included yet.** Payloads use a generic activity summary. Selecting an alert opens Notifications. Browser/OS grouping varies.
- Dynamic browser titles preserve unread counts. Public profiles/posts/articles use anonymous visibility filters for crawler metadata. Single-origin HTML includes canonical/Open Graph/Twitter metadata and a public summary; `/robots.txt`, `/sitemap.xml` and local branded text-only preview images are available. Image posts use their public image; articles use their cover. This is an initial SEO foundation, not full article-body server rendering or a ranking guarantee.
- About history/founder section, Help, guidelines, installation, advertising information, beta Privacy and Terms pages. The policy pages explicitly identify operator/contact/retention/data-request details that need completion before public launch.
- Advertising draft/review beta, disabled by default. Staff → Feature releases → Advertising drafts enables `/ads`. Members can save/edit their own drafts, optionally reference an eligible own post, request feed/community placement, set an NGN budget and dates, submit and cancel. `/admin/ads` requires `discovery.manage`; reviewers cannot approve their own campaign, and review decisions are audited. Approval does not activate delivery.
- No checkout, charges, spend ledger, sponsored feed delivery, impression/click counting or new ad-image upload path. These are future advertising-delivery work, not simulated results.

## Upgrade and setup
1. Stop the previous app terminal with Ctrl+C. Run `upgrade-from-v027.ps1 -OldProject <previous fpiupdates folder>`. The script creates a PostgreSQL backup and preserves environment files, uploads and Compose settings. All older migration SQL is retained unchanged.
2. Push stays disabled until configured. From `backend`, run `npm run push:configure -- --subject=mailto:YOUR_REAL_EMAIL`. Keys are saved to `.env` without printing the private key; existing keys are preserved. Set `WEB_PUSH_ENABLED=true`, restart the API and enable on each device from Settings → Notifications. Keep VAPID keys stable and secret.
3. Delivery needs a continuously running Node process, PostgreSQL and outbound HTTPS to browser push services. A sleeping free host cannot deliver promptly. Signing out stops that session's registered push delivery; sign in and enable again to reconnect. iPhone/iPad require a supported OS and a Home Screen web app. Device permissions, power restrictions and browser/OS state still apply. No Apple developer membership/app-store upload is needed for this PWA route.
4. Push is best effort, not an emergency channel or guaranteed instantaneous delivery. Dispatch checks run every 15 seconds, use a 60-second lease, retry ambiguous network failures and collapse alerts under a stable tag. Provider acceptance is not a read receipt. A two-second commit grace window reduces cursor races; this initial worker is not a large-scale durable transaction-outbox implementation.
5. Public sharing needs a reachable HTTPS deployment with `APP_URL` set to its public origin and `SERVE_FRONTEND=true` using the built frontend. Separate frontend hosts must proxy public HTML, `/og.png`, `/robots.txt`, `/sitemap.xml` and `/api` appropriately to the API host; a static SPA rewrite alone cannot provide dynamic crawler previews. Localhost cannot be previewed externally. WhatsApp/social preview caches are controlled by those platforms.
6. The sitemap includes public static pages and the latest 1,000 published articles. It does not enumerate every profile/post. Future growth needs paginated sitemap indexes, full public article rendering and search-console setup. Availability is checked on every preview request, but external services can retain older cached previews.
7. Other browsers cannot universally detect or open an installed PWA. Existing installed apps may retain the old icon until the browser refreshes the manifest or the user reinstalls. Do not erase browser data during an upgrade; unsent drafts may be lost.
8. No paid storage, payment provider, live ad delivery or external hosting has been enabled. Existing upload restrictions are preserved.

## Before public launch
Arrange real support/contact details, operator identification, retention and data-rights procedures, policy review, moderation coverage, backup-restoration and HTTPS device tests. Advertising additionally needs published pricing/refund terms, verified/idempotent payment handling, an atomic spending ledger, frequency caps and measured delivery before purchases open.

Primary implementation references: WebKit Web Push for iOS/iPadOS, web.dev PWA detection, Google Search Central JavaScript SEO and web-push-libs/web-push documentation.
